# Form Submission Delivery is its own table, one row per form-handoff Referral

The open/processing/closed relay lifecycle for getting a Referral's details to a supplier (currently a notification email to a configurable internal address) is stored in a new `formSubmissionDeliveries` table referencing `referralId`, rather than as status fields bolted onto `referrals`. `referrals.payoutState` already tracks a different, supplier-facing lifecycle (commission status); conflating the two would make `referrals` ambiguous about which "status" callers mean. Granularity is one delivery row per form-handoff Referral, not one per Lead or per dialog interaction — Supplier Fan-Out (ADR-0020) can add Referrals to a Lead at a separate point in time (or never), so there's no single moment to batch them into one row. Click-through and phone-based Referrals never get a Form Submission Delivery row, since they have no relay step today.
