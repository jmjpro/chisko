# Non-production self-seed skips the Smart Meter Registry / israelPlaces refresh by default

ADR-0012 made every brand-new Convex deployment self-seed via `POST /seed`, including triggering `smartMeterRegistryRefresh.doRefresh` and `israelPlacesRefresh.doRefresh` so the Smart Meter Registry and `israelPlaces` aren't empty on day one. CHI-72 fixed the delete-all/insert-all churn that made that data report >1GB of storage (ADR-0021), but the live data itself is still ~10-50MB, dominated by ~100k `smartMeterAddresses` rows — and every per-PR preview deployment (ADR-0011) plus every per-worktree local deployment pays that fetch-and-insert cost in full, on top of whatever production already holds. As preview/worktree deployments multiplied, this pushed the project up against Convex's usage quotas.

`/seed` now only seeds the Smart Meter Registry / `israelPlaces` data unconditionally on production (detected via `SENTRY_ENVIRONMENT === "production"`, the same env var convention `convex/lib/sentry.ts` already uses to tag error reports). On any other deployment it's opt-in via `?seedRegistries=true` on the `/seed` request; without it, `seedAll.runAll` still seeds the catalog (suppliers/plans/rates — a few KB, and required for prerendered pages to work at all per ADR-0012) but returns a message naming the skip, how to opt in, and the approximate storage cost (~10-50MB) so whoever's seeding a preview/worktree deployment can decide if they need that data for what they're testing (e.g. the Smart Meter Registry cascade or Place of Residence typeahead) before paying for it.

## Considered Options

- **Opt-in registry seed on non-production, env-detected (chosen)**: keeps every fresh deployment usable (catalog seed still automatic) while making the expensive, often-unneeded fetch explicit. Reuses the existing `SENTRY_ENVIRONMENT` convention instead of inventing a new production-detection mechanism. Costs an extra manual `curl ... /seed?seedRegistries=true` step on the rare preview/worktree deployment that actually needs registry data.
- **Leave registry seed automatic everywhere (status quo)**: rejected — this is what drove usage up against quota as ephemeral deployments multiplied; CHI-72's fix addressed storage *churn*, not the repeated fetch-and-insert cost itself.
- **Make the entire `seedAll` opt-in, including the catalog**: rejected — the catalog seed is tiny (a few KB) and ADR-0012's whole premise is that fresh deployments must not show empty pages; gating it would reintroduce that problem for no quota benefit.
- **Detect production via a new dedicated env var**: rejected — `SENTRY_ENVIRONMENT` already distinguishes production from non-production per deployment (ADR-0013) and is already set on every deployment that matters; a second variable would just be another thing to keep in sync.
