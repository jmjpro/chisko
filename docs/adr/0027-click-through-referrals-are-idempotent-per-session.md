# Click-through Referrals are idempotent per session+supplier+Plan Version

A naive redirect endpoint would log a new Referral on every click, but Electra's payout trigger is `perSignedContract` — a single attribution should map to a single Click ID, not fragment across however many times a user re-clicked (came back to compare, double-clicked, hit back/forward). `/out/:supplierId/:planVersionId` looks up an existing click-through Referral for `(sessionId, supplierId, planVersionId)` first; if found, it reuses that Referral's Click ID and just redirects, only inserting a new Referral row on the first click. The alternative — logging raw click volume as separate rows — was rejected because nothing in this product currently needs click-volume analytics separate from attribution, and conflating the two would make payout reconciliation ambiguous.
