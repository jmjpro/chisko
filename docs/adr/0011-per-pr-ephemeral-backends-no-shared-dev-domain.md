# Per-PR ephemeral backends instead of a shared dev domain

CHI-33 originally called for a persistent `dev.chisko.app` Vercel/Convex pair shared by all non-prod work. We dropped that in favor of giving every PR branch its own ephemeral Vercel preview deployment paired automatically with its own ephemeral Convex deployment (created on push, torn down when the PR closes/merges). There is no `dev.chisko.app` or `preview.chisko.app` domain — non-prod access happens through Vercel's auto-generated per-deployment/per-branch URLs. We chose this because a shared dev environment means concurrent PRs trample each other's data, while per-PR backends give full isolation with no extra CI scripting. Production remains the only stable custom domain (`chisko.app` / `www.chisko.app`), pointed at the production Convex deployment (`watchful-skunk-387`, team "jmjpro's team", project `chisko`).

Note: installing the Convex Vercel Marketplace integration always provisions a brand-new Convex team/project rather than linking an existing one — there's no UI path to point it at an existing project. We tried that route, then backed it out in favor of the manual connection method: a Production Deploy Key and a Preview Deploy Key generated from the existing `chisko` Convex project's dashboard, set as `CONVEX_DEPLOY_KEY` on Vercel's Production and Preview environments respectively.

Note: `npx convex deploy --cmd '<build>'` runs `<build>` *before* pushing functions/schema (per the CLI's own documented step order). Several of our pages query Convex during `astro build` itself (static prerendering), so on a brand-new preview deployment with no functions yet pushed, the build's query fails with `FunctionPathNotFound` — and since the failed `--cmd` aborts the deploy before the push step ever runs, the deployment can never bootstrap itself; every retry fails the same way. `vercel.json`'s `buildCommand` works around this by deploying twice: `npx convex deploy && npx convex deploy --cmd 'npm run build'`. The first call pushes functions and waits for indexes to finish building; the second call's `--cmd` then queries against functions that already exist (its own redundant re-push is a fast no-op).
