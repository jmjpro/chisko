# Smart Meter Registry and israelPlaces refreshes diff and insert only — never delete

`smartMeterRegistryRefresh.ts` and `israelPlacesRefresh.ts` previously deleted every row and reinserted the full dataset on each weekly refresh. Convex's document log only reclaims deleted rows after an ~80-day retention window, so this delete-all/insert-all churn was the cause of `smartMeterAddresses` reporting >1GB of storage for ~100k live rows of three small fields (CHI-72).

We changed both refreshers to diff the freshly-fetched source data against existing rows and insert only the new keys, never deleting rows that are no longer present in the source. We accept the resulting staleness risk — if IEC or data.gov.il ever drops an address/place from their dataset, it remains in our table indefinitely — because both sources are observed to be effectively append-only in practice (smart meters are not decommissioned, and Israeli localities are not deregistered), and the complexity of safe reconciliation isn't justified for a near-zero-probability case. This is a deliberate deviation from full reconciliation: a future engineer adding delete-on-removal logic should know this was a conscious trade-off, not an oversight.
